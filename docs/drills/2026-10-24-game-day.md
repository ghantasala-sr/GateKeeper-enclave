## The breakage (00:11:31 UTC, all at once)

1. Keycloak scaled to 0.
2. The backend's egress NetworkPolicy lost its database rule. The backends were restarted, as after a node
   upgrade, because connections that already exist survive a policy change.
3. The frontend set to an image tag that doesn't exist.

## What it showed

- **The design limited the damage.** With the frontend image refused, the surge-first rollout kept the old
  frontends serving; the bad image never ran. With the database blocked, the backends went not-ready without
  restarting, and came back without a restart once the policy was restored. Only Keycloak, a single replica, was
  a hard outage, the known gap.
- **The runbook's gap:** Helm 4 applies server-side. After `kubectl patch`, `kubectl set image` and `kubectl scale`,
  kubectl owns those fields, and a plain `helm rollback` is refused. The runbook now says `--force-conflicts`
  wherever it re-applies a release, and explains why.
- **Re-applying the release is the right fix for any hand edit.** One command restored all three things, because
  the release is the source of truth.

Expected time with the corrected runbook: about 3 minutes (first look, one rollback, rollouts).
